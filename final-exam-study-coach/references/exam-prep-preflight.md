# 期末前期准备预检

目标：当用户说要开始复习、冲刺、排期或新增材料时，先把“材料、考试时间、计划状态、下一步动作”整理成可执行系统，而不是只给建议。

## 触发场景

- 用户说“我要复习”“帮我安排”“期末快到了”“今天学什么”。
- 用户新增教材、PPT、课件、考试范围、图片课表、往年题或错题。
- 用户说之前没完成、偷懒了、计划乱了、材料又变了。
- 对话被压缩、跨天继续、或需要恢复长期带学状态。

## 预检顺序

1. **确认当前日期和考试时间**
   - 使用当前系统日期；图片或课表中的日期必须转成明确的年月日和时段。
   - 多门课时按考试先后排序，标出相邻考试间隔。
   - 如果考试时间缺失，不停止；标为“待验证”，先按材料和课程风险排临时计划。

2. **扫描材料变化**
   - 查看材料目录是否新增、删除、替换或下载完成。
   - 新增材料必须触发对应课程的 `material_inventory`、`course_model`、`review_input` 和 `review_plan` 更新。
   - 不允许继续使用明显过期的旧计划，例如课件从4章变成10章后仍按旧章节排。

3. **建立或刷新课程模型**
   - 每门课先判断核心问题、考试操作和高收益知识点。
   - 材料多时先生成材料清单和主题索引，再写计划。
   - 证据强度必须保留：`explicit`、`repeated`、`inferred`、`uncertain`。

4. **生成总控计划**
   - 多门课按考试顺序和提分收益排，不平均分配时间。
   - 第一门考试优先建立底盘；后面课程用短块提前启动，避免考完第一门才从零开始。
   - 输出至少包含：考试时间表、总策略、各科提分地图、未来3天任务、考试周切换、拖延修正规则。

5. **留下恢复检查点**
   - 长计划必须写一个检查点文件或等价状态块。
   - 检查点包含：考试时间、材料版本、计划版本、已完成、未完成、下一学习块、拖延后保留/压缩规则。
   - 上下文压缩后先读检查点，再继续当天任务。

6. **给第一学习块**
   - 不以“建议你先看看”结束；必须给25-90分钟可执行任务。
   - 第一学习块要写清：打开什么材料、做什么输出、怎么自测、学完如何回报。

## 拖延预留

- 默认学生会拖延，核心任务只占可用时间的70-80%。
- 如果按时完成，缓冲期改成错题回炉、间隔复习和混合模拟。
- 如果没完成，立即砍低证据低收益内容，保留高证据、高分值、高迁移内容。
- 任何补救计划都要安排一个能立刻开始的短任务，避免再次停在规划上。

## 产物命名建议

单门课：

- `material_inventory.md/json`
- `course_model.md/json`
- `review_input.json`
- `review_plan.md`
- `practice_*.md`

多门课：

- `final_exam_secretary_plan.md`
- `study_state_checkpoint.json`
- `prep_summary_and_skill_optimization.md`

## 验证门槛

完成前至少检查：

- 关键计划文件存在且非空。
- JSON 文件可以解析。
- 中文文本没有明显问号乱码或旧编码污染。
- 新增材料数量和计划中引用的材料范围一致。
- 主 skill 和安装后的 skill 都同步更新。
- 如果使用 skill 创建规范，运行校验脚本。

## 输出口吻

像私人秘书而不是问卷系统：

- 先给可执行安排，再列待验证信息。
- 说清今天第一步，而不是把用户推回材料堆。
- 用户偷懒时直接重排，不批评。
- 用户新增材料时自动更新计划，不让用户自己重新组织。
