# 通用学科建模

这个 skill 的核心不是记住若干课程模板，而是先把任何课程转成一个可操作的考试模型。课程专项包只能作为加速器，不能替代通用建模。

## 课程模型

接到任意学科材料后，先建立 `course_model`：

- `core_problem`：这门课反复追问的核心问题是什么。
- `knowledge_units`：知识单元类型，包括概念、事实、术语/符号、规则/公式、过程、方法/程序、案例、论证框架、作品/文本、技能表现、误区。
- `exam_operations`：考试要求学生做什么动作。
- `representation_modes`：最适合表达的形式，如文字框架、表格、流程图、公式、图像、案例链、代码、图纸、时间线。
- `evidence_sources`：判断重点的来源，如考纲、老师提示、往年题、作业、课堂重复、教材章末题、错题。
- `scoring_modes`：怎样给分，如关键词、步骤分、结论分、论证层次、案例匹配、格式规范、单位/边界检查。
- `practice_ladder`：从识别、基础、考试、迁移四层训练。
- `remediation_rules`：学生卡住时优先补哪种前置。

## 考试操作分类

把题型统一映射到这些操作，后续计划、练习、评分和补救都围绕操作展开：

- `recall`：背出、默写、列举、识别术语。
- `explain`：定义、解释原因、说明机制、用自己的话讲清。
- `compare`：比较、区分、分类、辨析相似概念。
- `calculate`：计算、求解、代入公式、数值判断。
- `derive_prove`：推导、证明、证明性质或结论。
- `solve_apply`：应用方法解决新题或案例。
- `analyze_case`：分析材料、案例、文本、数据或情境。
- `design_create`：设计方案、建模、绘制、写计划、提出结构。
- `critique_evaluate`：评价、批判、判断优劣、给出依据。
- `translate_interpret`：翻译、释义、读图、读表、解释结果。
- `implement_debug`：写代码、改错、模拟算法或流程。
- `diagnose_classify`：诊断、归类、识别病因/问题/类型。
- `write_argue`：论述、作文、证明性写作、观点组织。

## 学科族不是硬编码课程

需要时只把课程归入“训练方式相似”的学科族：

- 概念记忆型：重点是术语、定义、框架、对比。
- 程序计算型：重点是判型、步骤、公式、边界检查。
- 论证写作型：重点是观点、结构、证据、评分关键词。
- 案例解释型：重点是情境识别、概念匹配、因果链。
- 文本解释型：重点是文本细读、术语、论点、表达。
- 设计表现型：重点是约束、方案、图示、规范和迭代。
- 语言技能型：重点是输入积累、输出模板、纠错和迁移。

同一门课可以属于多个学科族。不要因为课程名陌生就退回“综合复习”；要用材料和题型推断它考什么操作。

## 输出顺序

1. 材料证据：列出材料和重点来源。
2. 课程模型：核心问题、知识单元、考试操作、评分方式。
3. 提分地图：按证据、分值、薄弱度、可修复性排序。
4. 理解卡：每个重点给通俗解释、助记、前置、误区、练习。
5. 练习阶梯：识别题、基础题、考试题、迁移题。
6. 缓冲计划：核心任务只排进 70-80% 时间，剩余作为拖延和回炉缓冲。
7. 检查点：每轮结束写当前状态、已完成、未完成、下一步和降级规则。
