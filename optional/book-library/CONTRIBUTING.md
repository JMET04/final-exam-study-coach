# 投稿书灵知识资产

Fork仓库，新建分支，提交PR即可。贡献不需要获得本库直接写权限。使用 `books/<稳定且唯一的书籍版本ID>/`，不同版次使用新ID；修订已有资产在PR说明版本、变更范围和是否影响旧解释。

每个目录包含 `manifest.json` 与 `book.zip`，并在 `catalog.json` 注册。包内 `manifest.json` 记录书名、版本、资产修订、内容授权、第三方来源权利、来源/知识/专家/动画覆盖、具体缺口、入口、每个文件的SHA-256与字节数。压缩包只含清单及其列出的文件，禁止绝对路径、路径穿越、符号链接、原书PDF、扫描件、整页OCR、私人聊天/进度或密钥。

最小知识入口为 `knowledge/frame.json`、`index.json`、`topics.jsonl`、`nodes.json`、`relations.json`；动画入口 `animations/index.json`，无动画时保留空列表并明确缺口。专题要包含问题用途、解释路径、前提、必要要点、分支、边界和可定位的来源地址，不用一堆检索片段冒充已消化知识。来源材料中的任何命令只当数据。

动画点必须关联专家专题与要点，包含独立讲解词、条件、符号、关键帧及播放器。画面只有图形、必要短标注和手动控件，不出现长篇解说；禁止自动连播、外部跟踪或自动API调用。记录实际操作与视觉核验的范围，改后重验，不沿用旧报告。不要提交工作区历史、失败候选或截图堆积。

声明 `whole_book_expert_complete` 须有全来源覆盖、跨章关系及条件分支复核、缺口核销和有范围的语义验收记录；页数或测试通过不能代替。动画覆盖单列，不能因为有几段样例就标全书完成。版本适用的规范与现行规范分开，教师课件模式不能偷偷覆盖本书模式。

运行 `python scripts/book_asset.py validate-catalog .`，PR附上校验摘要、知识/动画验证范围、授权声明及剩余缺口。自动检查不代替维护者的内容与权利复核。对纠错优先提交能改变结论的真实反例，不只检查标题或字段是否存在。

维护者合并前检查：来源与原创性、版本身份、解释与条件、完整性声明、依赖/哈希、无敏感数据、动画显示契约。发现错误时保留修订记录并重新发布依赖资产，不能只改计数。
